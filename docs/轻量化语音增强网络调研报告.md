# 轻量化语音增强网络调研报告

> **用途**：LRAC 2.0 挑战赛"codec 前端增强模块"选型参考 / 团队方案对齐材料
> **调研人**：梁鸣轩 ｜ **日期**：2026-09-04 ｜ **状态**：v1.0（一手实测数据持续补充中）

---

## 1. 背景与任务定位

LRAC 2.0（Cisco 主办的低资源音频编解码挑战赛）中，团队主攻 Track 1（透明音质编解码），并计划延伸覆盖 Track 2（≤1.5M 参数的内存高效版本）。增强模块在系统中的定位是 **codec 的前端**：带噪/含混响输入 → 语音增强 → 编解码，用以提升整个系统对真实声学环境的鲁棒性。

该定位对增强模块提出了三条硬约束，也是本调研的筛选口径：

1. **轻量**：需与 codec 共享端侧算力预算，参数量以 100K 级为候选门槛（老师指定的 GTCRN 48.2K / LiSenNet 37K 即此口径）；
2. **可流式/低延迟**：实时通信场景要求因果或低 lookahead 推理；
3. **可实测**：必须有可获得的预训练权重或可复现的训练配置——"纸面模型"不进候选。

## 2. 调研方法与信息来源

- **文献**：arXiv 全文（HTML）、IEEE/ISCA 论文页、官方博客（Samsung Research 等）；
- **代码**：官方 GitHub 仓库 README 与推理脚本；
- **一手数据**：本机（RTX 4060 笔记本）已搭建统一封装与测试管线，自建 6 类噪声 × 2 档信噪比测试集（详见 §8）。

**可比性声明**：表中论文成绩均为各工作自报，训练/测试条件不一，横向数值仅供参考；最终排序以本组统一 testset 实测为准。

### 3.1 各模型处理域速查

| 模型 | 处理域 | 说明 |
|---|---|---|
| GTCRN | 频域-复数谱 | STFT 512/256，ERB 频带映射，输入/输出复数谱 |
| LiSenNet | 频域-子带复数 | STFT 512/256（32ms 窗/16ms 帧移），子带+双路因果 GRU |
| UL-UNAS | 频域 | STFT 512/256（32ms/16ms），NAS 搜索的频域块 |
| FSPEN | 频域-全带+子带融合 | 采样率细节待查 |
| MetricGAN+ | 频域-幅度谱掩码 | 生成掩码乘幅度谱，相位沿用带噪相位 |
| SepFormer | **时域** | 波形进出，与采样率转换最兼容 |
| DTLN | 时频两级 | STFT + 可学习特征变换两级 LSTM |
| Dense-TSNet | 频域-幅度谱 | STFT 400/100，两阶段密集连接 |
| RNNoise / PercepNet | **混合（DSP+NN）** | 手工 ERB/音高特征 + 小 GRU；PercepNet 48k 全带 |

**"域"为什么重要**：时域模型换采样率最省心；频域模型的 STFT 参数与 16k 绑定，接 24k 管线必须重采样；混合域延迟最低、可解释性最好；另外频域增强将来有机会与 codec 的分析窗共享 STFT 结果省算力——这是"增强挂 codec 前"的独特红利。

> **轻量口径的代际变化**：2020 年"轻量"的标杆是 DTLN 的 ~1M，2024 年已缩水到 ~50K 级——**20 倍**。老师指定 GTCRN/LiSenNet 正是这一代超轻量模型的代表。

## 4. 候选模型分述

### 4.1 GTCRN ★ 推荐打底（已接入）

- **架构**：分组时间卷积 + RNN（GTCRNN），ERB 频带映射降低计算；论文原报 23.7K 参数，加非学习 ERB 参数后为 48.2K；
- **流式**：官方 `stream` 实现（i5-12400 CPU 上 RTF 0.07）；为可流式化，将分组 RNN 的显式特征重排改为后续 FC 层隐式完成；
- **成绩**：VCTK-DEMAND 上 PESQ 2.87 / STOI 0.940，同表对比 RNNoise 2.29、DeepFilterNet v1 2.81；
- **工程性**：权重开箱即用（DNS3 训练版 + VCTK-DEMAND 训练版）；本组已将其与 SpeechBrain 基线封装进同一接口和对比 demo；
- **风险**：16k 采样率（若管线为 24k 需重采样）；超轻量模型在 babble/music 类困难噪声下的表现需实测确认（见 §8）。

### 4.2 LiSenNet ★ 论文成绩最佳，但有复现成本

- **架构**：子带分解 + 双路建模（时间轴单向 GRU 保因果，频率轴帧内 BiGRU）；含噪声检测器变体（+ND，静音段计算量可降至 15M MACs/s）；
- **成绩**：VB+DEMAND 上 PESQ 3.07 / STOI 0.939，为其对比表中全场最高（FSPEN 2.97、FullSubNet 2.89、DCCRN 2.78、RNNoise 2.33）；相对 FSPEN 以 47% 参数、63% 计算量换来 +0.1 PESQ；
- **关键短板**：官方仓库**不提供预训练权重**（仅训练框架，MIT 协议，需 `--ckpt_path` 指定自训权重）——采用它意味着一笔复现训练的算力/时间投入；
- **决策点**：是否投入复现，取决于服务器算力富余度与 codec 管线对精度的要求，建议对齐会讨论。
- **本组一手实测（2026-09-05 补充）**：发现第三方 ONNX 重训版权重（claroche1/LiSenNet，HF，VoiceBank-DEMAND 16k，含流式/INT8 导出）并接入本组统一接口实测。结果：中等噪声（10dB）下有效（fan 类 SI-SDR 5.0→9.9），但 **0dB 重噪声全线低于不增强基线**（12 条平均 SI-SDR 4.50 vs 基线 4.99，PESQ 1.65 vs 1.73 亦劣于基线）——第三方重训版鲁棒性不足的实证，反而支持"选它就必须复现官方训练"的判断，与 GTCRN（同测试集平均 SI-SDR 9.86、0dB 稳态噪声仍 +6dB）形成鲜明对比。

### 4.3 FSPEN ★ 建议增补的第三实测候选

- **架构**：全带 + 子带融合网络（全局 + 局部特征），Samsung Research 出品，ICASSP 2024；
- **工程性**：官方 PyTorch 代码开源（注意：**论文原始参数设置有误，以仓库代码为准**）；社区另有流式推理实现；
- **成绩**：VB+D PESQ 2.97（引自 LiSenNet 论文对比表，79K 参数 / 89M MACs/s）；
- **待查**：采样率具体值、官方权重发布情况——需读仓库代码确认。
- **接入受阻（09-07 更新）**：官方仓库仅含模型定义，无权重无推理脚本；找到社区 Lightning 权重（iliasslasri/fspen，HF），但解剖其 state_dict 发现键名体系（fullband_encoder / dpe.blocks / feature_merge / subband_decoder）与官方 model.py（dprnn / subbandEncode / featureMerge）**完全不匹配**——权重来自另一个未公开的重实现框架。接入需跨框架键名映射，风险高收益低 → **降级为观察名单**，第三实测候选位让给 UL-UNAS（权重仓库内置、checkpoint 格式与 GTCRN 一致）。

### 4.4 H-GTCRN（受限候选）

Interspeech 2025（Samsung），GTCRN 基座的**双通道**混合系统，面向低信噪比场景，已发 checkpoint。因需双麦克风输入，与我们的单通道编解码场景不匹配，列为观察，不作实测。

**前沿区两条结论**：

1. **UL-UNAS 是"下一代候选"头名**：GTCRN 同作者（Xiaobin-Rong）用 RL-based NAS（PPO 搜索 ~10¹² 空间、MACs 感知奖励）搜出的 169K 模型，**零前瞻**（对比 LiSenNet 需要 32ms 前瞻），同算力下在其 DNS3 对比中压过 GTCRN（2.10）与 LiSenNet（2.23）。若其仓库提供权重，接入成本预计与 GTCRN 相当。**建议对齐会提议："GTCRN 打底 → UL-UNAS 跟进"是同一条演进线的两代**，比引入陌生团队的新模型更稳；
2. **RT-SEMamba 是蒸馏路线的公开课**：其渐进 KD 配方（输出级幅度/相位/复数 = 1.0/0.3/0.5、特征级取教师各块平均、前 10% 步数 ramp-up）把 1 层学生的 PESQ 从 3.06 提到 3.18 且推理快 2.75×——§9 第 5 条"自制蒸馏学生模型"路线的现成参考实现。

**UL-UNAS 一手实测（09-07 补充，本组统一接口 + 固定测试集）**：权重仓库内置（DNS3 版），已接入。结果：SI-SDR 9.86 / PESQ 1.95 / STOI 0.689 / LSD 17.9——**与 48.2K 的 GTCRN 几乎完全打平**（GTCRN：9.86 / 1.98 / 0.709 / 17.4），分噪声类型逐项对齐（babble 同为软肋：4.90 vs 4.77）。**结论：NAS 用 3.5 倍参数没有换到本测试分布上的收益，GTCRN 的参数效率更高；但 UL-UNAS 自带零前瞻流式推理与 ONNX 导出，部署属性更优。轻量线最终推荐维持 GTCRN 打底。**

**体系性资源：URGENT Challenge（Interspeech 2024/2025）**

通用鲁棒增强挑战赛，失真类型（噪声/混响/削波/丢包/带宽受限）与 LRAC 高度重叠；2024 版设低复杂度约束，2025 版资格线含参数限制；参赛开源系统多为 ESPnet 生态。**LRAC 官方数据仓库 README 明确提到"非 URGENT 2025 fork"，说明两个圈子高度重叠**——URGENT 的开源系统是现成的鲁棒增强方案库。

**战略方向：知识蒸馏定制学生模型（重点）**

已有成熟研究将大型 SE 模型蒸馏为亚 100K 因果小模型（arXiv 2309.08144），RT-SEMamba 用渐进 KD 做质量-延迟权衡。**对我们的长期含义**：前端不一定非要"从现成小模型里挑"，可以选择效果最好的大模型当教师，蒸馏出针对我们数据（24k、噪声谱型）定制的学生模型——与 Track 2 的模型压缩工作共享方法论，是"调研选型"之上的第二阶段路线。

## 5. 半候选：DeepFilterNet2

- 2.31M 参数（v1 1.8M → v2 2.3M），**48k 全频带**，帧级因果，嵌入式设备实时定位；
- **杀手锏**：全场唯一与 LRAC 24k 数据采样率最接近的成熟方案，且 `pip install deepfilternet` 即装即用，接入成本最低；
- **定位建议**：若团队确认 24k 管线，作为"采样率匹配优先"策略的实测备选；参数量超出轻量口径需在报告中说明取舍。

## 6. 观察名单：Dense-TSNet

- ~14K 参数（当前调研中最小），VB+D PESQ 3.05；
- **不可实测**：代码"录用后放出"，现无权重；**未讨论流式**；
- 附加发现：其 MACs 换算后可能高于 GTCRN——**参数量最小 ≠ 计算量最小**，评估需双指标并列；
- 论文的消融发现值得引用：Metric Loss（以 PESQ 为判别器）可刷高 PESQ 但引入"伪幻觉失真"、损害主观听感，作者最终置零该项——**客观分数与主观质量的背离**，支撑本组"多噪声听测 + 客观指标"双轨评估的方法论。

## 8. 一手实测（进行中）

- **平台**：RTX 4060 笔记本（CPU/GPU 双模式），统一封装接口（输入任意音频 → 16kHz 单声道 → 增强输出）；
- **测试集**：YESNO 干净语音 × {white, pink, fan, hum, babble, music} × {10dB, 0dB}，共 12 条；后续补充手机实采真实噪声；
- **待填表**：GTCRN / MetricGAN+ / SepFormer 在 12 条上的听测结论与推理耗时（本周内完成 GTCRN 行）。

## 9. 结论与建议

1. **GTCRN 为当前综合最优的打底候选**：权重开箱即用 + 官方流式实现 + 有第三方对比数据，三占；本组已完成接入，进入实测阶段；
2. **LiSenNet 成绩最高但需复现训练**：建议评估服务器算力富余后再决定投入；若复现，其 +ND 噪声检测器对静音段省算力的特性与 codec 前端场景天然契合；
3. **FSPEN 建议增补为第三实测候选**（有代码、有流式版、79K）；**DeepFilterNet2 作为 24k 管线的备选**（采样率匹配 + 零成本接入）；
4. **待团队确认的两个接口问题**：① 最终 codec 管线采样率是否为 24k（决定增强模块"内外重采样"设计）；② 对增强模块有无实时/流式要求（决定按流式还是离线接口封装）；
5. **长期方向（第二阶段路线）**：不局限于"选现成小模型"——用效果最好的大模型当教师，蒸馏出针对本组数据（24k、目标噪声谱型）定制的轻量学生模型，与 Track 2 压缩工作共享方法论（参考 §4.5 战略方向）。
