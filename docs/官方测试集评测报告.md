# 官方测试集评测报告

> 项目：LRAC 2.0 挑战赛 · 增强前端模块
> 执行人：梁鸣轩 ｜ 日期：2026-09-14 ｜ 版本：v1.1
> 对应任务：使用赛题官方测试集进行测试并给出音质指标参数

---

## 摘要

在官方 open-test-set（2025 版，**1100 条**有效测试样本）上，用统一接口对 **5 个增强系统**做了四项客观指标的全参考评测：

- **噪声条件收益明确**（700/1100 条）：最佳系统 UL-UNAS 在 track_1/noise 上 PESQ **2.230 → 3.120**、SI-SDR **+1.75dB**；track_2/noise 上 PESQ **1.438 → 2.365**、SI-SDR **+6.72dB**；
- **混响条件无额外收益，但不构成功能缺口**（400/1100 条）：各系统相对不增强基本中性（PESQ 1.240→1.326，SI-SDR 持平），无系统劣化。经核实，官方对该维度的要求是**鲁棒性/不劣化**（DCR 与输入参照比较），**并非去混响**，故现状属可接受区间；
- **发现一处必须修复的硬伤**：管线（24k→16k 处理→24k）导致增强输出 8kHz 以上能量只剩输入的 **1/31**，对 24kHz 透明编解码构成保真损失，且现有 16kHz 指标口径无法察觉；
- **选型结论更新**：官方真实噪声数据上 UL-UNAS 全面反超 GTCRN，建议 **UL-UNAS 优先、GTCRN 作参数效率备选**；
- **评分口径（本次核实）**：官方最终排名依据**众包主观听测**（MUSHRA-1S / DCR / DRT），**客观指标不计入最终得分**。本报告指标用于内部筛选与迭代；**主观验证是目前最大的缺口**。

## 一、工作内容

1. **数据获取**：定位并下载官方测试数据（稀疏检出，仅拉取所需子集，3100 个 wav / 843 MB）；
2. **元数据分析**：解析各子集 `meta.csv`，确认语种、采样率、信噪比分布与参考音频配对关系；
3. **评测执行**：编写官方测试集评测脚本，对 5 个系统 + 不增强基线完成 1100 条 × 4 条件的全量评测（本机 RTX 4060，约 110 分钟）；
4. **结果分析**：分条件汇总指标、量化带宽损失、核实官方评分口径（含混响要求的真实性质）、修正此前基于小样本的错误结论。

> 注：官方 2026 的正式测试集（withheld set）将在测试阶段发放；本报告使用的是官方公开、允许用于开发验证的 2025 open test set。

### 官方评分口径（本次核实，重要）

| 测试项 | 内容 | 语言 | 码率 |
|---|---|---|---|
| MUSHRA-1S | 干净语音质量（隐藏干净参考 + 低锚点） | 英 / 西 / 中 | 12、32 kbps |
| **DCR** | **轻度噪声与混响鲁棒性，与输入参照比较** | 仅英语 | — |
| DRT | 可懂度（中文含辅音与声调） | 英 / 西 / 中 | 仅 1 kbps |
| 同时说话人 | 说话人保持 | 英语 | 12、32 kbps |

三点关键含义：

1. **最终排名完全依赖主观听测**，客观指标不参与最终得分（可能仅用于提交过多时的资格筛选）——本报告指标的价值在于**内部筛选与快速迭代**；
2. **混响是"鲁棒性"要求，不是"去混响"要求**。官方原文为 "Robustness to mild real-world distortions, e.g., background noise, reverberation"，DCR 以**输入信号**为参照，问听众"相比输入劣化了多少"；官方未提出任何去混响评分要求；
3. **DCR 口径下"过度处理会被扣分"**：与输入差异过大（引入失真）即视为劣化，因此"保守不劣化"在混响/噪声条件下反而是正确策略——这与"尽量多降噪"的直觉不完全一致。

## 三、评测方法

- **被测系统（5 个）**：GTCRN（48.2K）、UL-UNAS（171.3K）、LiSenNet（37K，第三方 ONNX 重训权重）、MetricGAN+（1.90M）、SepFormer（25.61M，重型参照）；另设**不增强基线**用于计算提升量；
- **接口**：统一增强模块（输入带噪波形 → 内部 16kHz 处理 → 输出 24kHz），所有系统共用同一调用路径；
- **指标**：PESQ（ITU-T 感知质量）、STOI（可懂度）、SI-SDR（保真度，dB，越高越好）、LSD（对数谱距离，dB，越低越好）；
- **计算口径**：指标在 **16kHz** 上计算（PESQ 仅支持 16k/8k），参评双方均重采样至 16kHz，保证同源可比；参考为消声干净音频；
- **样本量**：每条件的**全部样本**参与统计（非抽样），均值即该条件得分。

> **口径差异提醒**：本报告全部为"与干净参考比较"（可衡量降噪收益），而官方 DCR 为"与输入比较"（衡量是否劣化）。两者的结论方向可能不同，建议后续补充"输入参照"代理指标以贴合官方口径。

## 五、核心发现

1. **选型结论更新：UL-UNAS 优先，GTCRN 作参数效率备选。** 官方真实噪声数据上 UL-UNAS 在两个噪声条件全面领先 GTCRN（PESQ 3.120 vs 2.928；2.365 vs 2.180），并自带零前瞻流式推理与 ONNX/INT8 导出；GTCRN 以 48.2K 参数（UL-UNAS 的 28%）达到其约 95% 水平，仍是参数受限场景首选。合成测试集上两者打平，差异在真实噪声下才显现。

2. **混响条件：无额外收益，但不构成功能缺口（结论已修正）。** 官方 reverb 条件下六个系统相对"不增强"基本中性（PESQ 1.240→1.326，SI-SDR 持平），无系统出现实质劣化。经核实官方 Evaluation 口径，混响属于**鲁棒性要求**，由 **DCR 与输入参照比较**评估，**未要求去混响**。因此当前状态属可接受区间；该维度真正需要确认的是"增强是否在混响/噪声输入下引入劣化"，而非投入去混响能力。

3. **"单看 PESQ"会得出完全错误的结论。** MetricGAN+ 在两个噪声条件 PESQ 均位列前二（2.876 / 2.012），但 SI-SDR 比不增强低 **4.60～11.34 dB**（保真严重崩坏）。该现象在自建合成集与官方集上**两次独立重现**；且在 DCR 口径下，这类"过度处理/引入失真"很可能被听众判为劣化，风险比指标显示的更大。

4. **第三方 LiSenNet 权重确认不可用。** 官方数据上 SI-SDR 一律低于基线（−4.44 / −1.04 dB），分片复测（前/中/末各 15 条）结果一致（−3.3～−6.3dB）。若需使用 LiSenNet 的效果，必须复现官方训练。

5. **增强输出的高频被丢弃（硬伤）。** 实测频谱：8kHz 以上能量占比 —— 带噪输入 0.31%、干净参考 0.31%、**增强输出 0.01%（约 1/31）**。原因是管线使用 16kHz 模型（24k→16k 处理→24k），8–12kHz 信息被移除。对 24kHz 透明编解码构成保真损失，而现有 16kHz 指标口径**无法察觉该问题**。

## 六、局限与待验证项

| 项 | 状态 | 说明 |
|---|---|---|
| **主观听测** | ⚠️ **最大缺口** | 官方最终排名完全依据众包主观听测（MUSHRA-1S / DCR / DRT），客观指标不计入最终得分；本报告全部结论均基于客观指标，尚无任何 24k 主观验证 |
| DCR 口径未复现 | ⚠️ 未做 | 官方 DCR 为"与输入参照比较"，本报告均为"与干净参考比较"；需补"输入参照"代理指标 |
| 语言覆盖 | ⚠️ 缺口 | 官方 2025 测试集为纯英语；2026 新增西班牙语/中文（MUSHRA 与 DRT 均覆盖），需等 withheld 集发放或另建替代验证材料 |
| 端到端效果 | ⚠️ 未验证 | 本报告测的是"增强后 vs 干净参考"；真实链路为"增强 → codec → 解码"，增益能否传导至最终音质需 codec 就位后验证（若 codec 训练数据含噪，前置增强亦可能造成分布不匹配） |
| 样本量纪律 | 已纠正 | 中途一次 15 条小样本快测因脚本变量复用 bug 叠加样本过小得出错误结论，已由全量数据与分片复测纠正；**结论一律以全量样本为准** |
| 24k 增强模型 | 待评估 | DeepFilterNet2（48kHz 全带）可作为原生宽带处理的候选，尚未接入 |

## 七、下一步建议（按性价比排序）

1. **补齐主观听测能力（最高优先）**：官方得分完全取决于主观听测（MUSHRA-1S / DCR / DRT），而本组尚无 24k 主观验证手段。建议基于现有 demo 扩展"参考 / 输入 / 增强"三点 MUSHRA 式盲测工具，先在组内盲测——这是唯一能提前暴露"听起来行不行"的手段；
2. **补"输入参照"代理指标（低成本）**：按 DCR 口径计算"增强输出 vs 带噪/混响输入"，核查各模型在"不劣化"标准下是加分还是减分（预计过度处理的模型在此口径下会暴露问题）；
3. **修复高频损失（约半天）**：最简方案为"高频保留"——增强输出负责 0–8kHz，8–12kHz 取原始带噪信号的高频带补回；更彻底方案是接入原生 24kHz/48kHz 处理的模型（DeepFilterNet2）；
4. **端到端验证（依赖 codec 进度）**：codec 就位后测"增强 → 编解码"链路的最终音质；
5. **多语言验证材料**：待 withheld 集发放，或先用公开中文/西语语料搭建替代验证集；
6. **（可选，非必需）去混响**：官方无此要求；若团队有余力、希望争取混响条件下的额外增益，可再考虑接入去混响模型或利用官方 RIR 数据（MOTUS、DNS5）联合训练。

## 八、复现方式与产出清单

**数据**：`official-testset/LRAC-2025-test-data/open-test-set/`（稀疏检出，843 MB）

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/cisco/multilingual-speech-testing.git official-testset
cd official-testset && git sparse-checkout set LRAC-2025-test-data/open-test-set
```

**评测**：

```bash
python official_eval.py               # 全量（1100 条 × 6 系统，本机约 110 分钟）
python official_eval.py --limit 20    # 快速抽样
python official_eval.py --models gtcrn,ulunas
```

**产出文件**：

| 文件 | 内容 |
|---|---|
| `official_result.md` | 四条件完整指标表（本报告第四节数据源） |
| `official_result.json` | 结构化结果，便于后续对比/绘图 |
| `official_eval.py` | 官方测试集评测脚本（可复用于后续新模型） |
