# 轻量化增强模型：调研与实测简报

> 梁鸣轩 ｜ 2026-09-14 ｜ 对应任务：调研轻量化增强网络 → GTCRN 串链路 → 定义接口 → 固定测试集对比效果与参数量（含处理域）→ 官方测试集评测

---

## 一、调研结论

按四道筛选口径（参数量 ≤100K 级 / 流式支持 / 权重可得 / 输入域匹配）排查 15+ 个模型：

- **可实测（5 个，全部已接入）**：GTCRN、UL-UNAS、LiSenNet、MetricGAN+、SepFormer（基线参照）
- **淘汰 / 受阻（各有记录）**：FSPEN（社区权重与官方代码架构不匹配）、CoFi-Lite（官方仓库为占位符）、Dense-TSNet / ABS-HUNet（无权重）、AdaptCRN（仓库仅演示页）、TSDCA-BA（训练归一化统计未公布，不可复现）、LAU-Net（输入域为骨导加速度计，非麦克风语音）

### reverb 条件（track_1 200 条 + track_2 200 条）

各系统相对"不增强"**基本中性**（PESQ 1.240→1.326、1.243→1.309；SI-SDR 持平），无一系统实质劣化。经核实官方口径，混响属**鲁棒性要求**（DCR 与输入参照比较），**并非要求去混响**，故现状属可接受区间（详见"四、核心发现 2"）。

> 说明：官方 2025 测试集为**英语**；2026 新增的西班牙语/中文需等官方 withheld 测试集在测试期发放后方能覆盖。

### 官方评分口径（本次核实）

| 测试项 | 内容 | 语言 | 码率 |
|---|---|---|---|
| MUSHRA-1S | 干净语音质量（隐藏干净参考） | 英 / 西 / 中 | 12、32 kbps |
| **DCR** | **轻度噪声与混响鲁棒性，与输入参照比较** | 仅英语 | — |
| DRT | 可懂度（中文含辅音与声调） | 英 / 西 / 中 | 仅 1 kbps |

**最终排名完全依赖众包主观听测，客观指标不计入最终得分**（可能仅用于资格筛选）——因此本组指标用于内部筛选与迭代，而主观验证是当前最大缺口。

## 四、核心发现

1. **前端选型调整为 UL-UNAS 优先、GTCRN 作参数效率备选**：官方数据上 UL-UNAS 在噪声条件全面领先（track_1 PESQ 3.120 vs 2.928；track_2 PESQ 2.365 vs 2.180），且自带零前瞻流式与 ONNX/INT8 导出；GTCRN 以 48.2K 参数（UL-UNAS 的 28%）达到其约 95% 水平，仍是参数受限场景首选；
2. **混响：无额外收益，但不构成功能缺口**：官方对该维度的要求是"鲁棒性/不劣化"（DCR 与输入参照比较，原文 "Robustness to mild real-world distortions, e.g., background noise, reverberation"），**并未要求去混响**；实测各系统在混响输入下均未实质劣化，故现状可接受。需做的是确认增强不引入劣化，而非投入去混响；
3. **MetricGAN+ 的"指标陷阱"两次重现**：官方数据上 PESQ 位列前二（2.876 / 2.012），但 SI-SDR 比不增强低 4.6～11.3dB。**单看 PESQ 会得出完全错误的结论**；且在 DCR 口径下这类"过度处理"很可能被判为劣化，风险更大；
4. **第三方 LiSenNet 权重确认不可用**：官方与自建测试集上均劣于基线（SI-SDR −1.0～−4.4dB），要用它必须复现官方训练；
5. **增强输出丢失高频（自研管线硬伤）**：8kHz 以上能量只剩输入的 **1/31**（0.31%→0.01%），因管线用 16kHz 模型处理 24kHz 数据；对 24k 透明编解码是保真损失，而 16kHz 指标口径看不见它，须修；
6. **语言覆盖有缺口**：官方 2025 测试集为纯英语，2026 新增西语/中文（MUSHRA 与 DRT 均覆盖），需待 withheld 集发放后补测。

## 五、已交付的接口（换模型只改适配器）

- `enhance_module.py`：基类统一入口（输入任意采样率带噪波形 → **输出 24k 增强波形**，官方管线口径；内部统一 16k 处理），新增模型 = 写一个适配器类 + 注册表加一行；
- `benchmark.py` / `evaluate.py` / `official_eval.py`：合成与官方测试集一键评测，自动产出对比表（本简报表格即由脚本生成）。

## 六、官方约束核对与待讨论

**官方 Rules 已明确（无需再确认）**：采样率 24kHz 单声道；总延迟 ≤30ms（算法+缓冲，两 track 均适用）；总计算 ≤700 MFLOPS；码率 1/6/12/24/32 kbps 五档 CBR；Track 2 另有 ≤1.5M 参数硬限制。

**待讨论**：

1. **增强前端与 codec 共享 30ms 延迟预算**：STFT 512 系模型单窗延迟已约 32ms，串入实时链路会超预算；可行方向是改用流式低延迟版本（GTCRN stream、UL-UNAS stream ONNX 均现成）；
2. **主观听测能力建设（最高优先）**：官方得分完全取决于主观听测，建议基于现有 demo 扩展 MUSHRA 式盲测工具（参考 / 输入 / 增强三点对比），先在组内盲测；
3. **修高频损失**（半天工作量）与**补"输入参照"代理指标**（贴合 DCR 口径）；
4. LiSenNet 若复现官方训练，需评估服务器 GPU 算力。
